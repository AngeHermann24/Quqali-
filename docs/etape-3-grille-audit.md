# ÉTAPE 3 : Grille de notation et audit

## 1. Principes de la grille

### Barème de 0 à 5 (le même pour tous les sous-critères)

| Note | Niveau | Signification |
|---|---|---|
| 0 | Absent / dangereux | Inexistant, ou risque pour l'usager |
| 1 | Très insuffisant | Manquements graves et visibles |
| 2 | Insuffisant | Plusieurs manquements |
| 3 | Acceptable | Conforme au minimum, sans plus |
| 4 | Bon | Conforme et maîtrisé, défauts mineurs |
| 5 | Excellent | Exemplaire, au-delà des attentes |

> Repère utile : **4/5 = 80 %**. Pour être admis, un établissement doit donc être « Bon » en moyenne sur l'ensemble de la grille.

### Règles de notation
- **Photo** : possible sur chaque sous-critère. Elle est **obligatoire** si la note est de 2 ou moins (preuve du manquement) et sur tous les points critiques, quelle que soit la note.
- **Commentaire** : obligatoire si la note est de 2 ou moins.
- **Non applicable (N/A)** : autorisé si le service n'existe pas (par exemple pas de piscine). Le sous-critère est alors retiré du calcul. Les points critiques ne peuvent pas être N/A.
- **Points critiques [C]** : ils comptent double. Une note de 1 ou moins sur un point critique entraîne la **non-admission, même si le score dépasse 80 %**.
- **Santé** : aucune photo ne doit montrer le visage d'un patient ni un document médical nominatif.

### Pondération (modifiable par l'admin, avec historique des versions)

| Critère | Poids |
|---|---|
| Hygiène (H) | 30 % |
| Accueil (A) | 25 % |
| Présentation du personnel (P) | 20 % |
| Gouvernance (G) | 25 % |

## 5. Calcul automatique du score

### Formules
- **Score d'un critère** = Σ (note × poids du sous-critère) ÷ Σ (5 × poids du sous-critère) × 100
  - Poids par défaut : **1** pour un sous-critère normal, **2** pour un point critique.
  - Les sous-critères notés N/A sont exclus.
- **Score global** = 0,30 × Hygiène + 0,25 × Accueil + 0,20 × Présentation + 0,25 × Gouvernance
- **Admission** : score global **≥ 80,0 %** et **aucun point critique noté 1 ou moins**.
- **Arrondi** : le score affiché est arrondi **à la décimale inférieure** (79,96 s'affiche 79,9, ce qui est non admis). On n'arrondit jamais au-dessus pour franchir le seuil.

### Exemple : un hôtel
Calcul du critère Hygiène :

| H1 | H2 [C] | H3 | H4 | H5 | H6 [C] | H7 | H8 |
|---|---|---|---|---|---|---|---|
| 4 | 5 (×2) | 4 | 4 | N/A | 5 (×2) | 4 | N/A |

Points obtenus : 4 + 10 + 4 + 4 + 10 + 4 = **36**. Maximum possible : 5 × 8 = **40**. Hygiène = **90 %**.

Score global :

| Hygiène | Accueil | Présentation | Gouvernance |
|---|---|---|---|
| 90 % | 80 % | 75 % | 78 % |

0,30 × 90 + 0,25 × 80 + 0,20 × 75 + 0,25 × 78 = 27 + 20 + 15 + 19,5 = **81,5 %**, donc **ADMIS**.

Même hôtel avec G3 (sécurité incendie) noté 1 : **NON ADMIS**, malgré un score supérieur à 80 %.

### Logique du calcul (version de référence, exécutée côté serveur)
```ts
type Note = 0 | 1 | 2 | 3 | 4 | 5 | null; // null = N/A

interface SousCritere { code: string; poids: number; critique: boolean; note: Note }
interface Critere { code: 'H' | 'A' | 'P' | 'G'; poids: number; sousCriteres: SousCritere[] }

const scoreCritere = (c: Critere) => {
  const notes = c.sousCriteres.filter((s) => s.note !== null);
  const max = notes.reduce((t, s) => t + 5 * s.poids, 0);
  const obtenu = notes.reduce((t, s) => t + (s.note as number) * s.poids, 0);
  return max ? (obtenu / max) * 100 : 0;
};

export const resultatAudit = (criteres: Critere[], seuil = 80) => {
  const totalPoids = criteres.reduce((t, c) => t + c.poids, 0);
  const brut = criteres.reduce((t, c) => t + c.poids * scoreCritere(c), 0) / totalPoids;
  const echecsCritiques = criteres.flatMap((c) =>
    c.sousCriteres.filter((s) => s.critique && s.note !== null && s.note <= 1).map((s) => s.code),
  );
  return {
    global: Math.floor(brut * 10) / 10,
    parCritere: Object.fromEntries(criteres.map((c) => [c.code, Math.floor(scoreCritere(c) * 10) / 10])),
    echecsCritiques,
    admis: brut >= seuil && echecsCritiques.length === 0,
  };
};
```
Le calcul officiel est **refait par le serveur** (fonction Supabase) au moment de la soumission. On ne se fie jamais au calcul fait sur le téléphone.

## 6. Interface mobile de l'agent

### Proposition anti-biais
**L'agent ne voit ni le score global ni le seuil pendant qu'il note.** Il voit seulement sa progression (le nombre de sous-critères remplis). Ça évite la tentation d'ajuster une note pour atteindre ou rater les 80 %. Le score s'affiche après la soumission.

### Ergonomie de terrain
- **Gros boutons** de 0 à 5, utilisables d'une main.
- **Un sous-critère par écran**, avec la consigne « À vérifier ».
- **Saisie vocale** du commentaire.
- **Ordre libre** : on peut sauter un sous-critère et y revenir. Le récapitulatif signale ce qui manque.
- **Blocage de la soumission** tant qu'il manque une note, une photo obligatoire ou un commentaire obligatoire.

### Fonctionnement avec une connexion faible ou absente
- **Application web installable** (Next.js), qui marche hors connexion. La grille et la fiche de l'établissement sont **téléchargées dès l'acceptation de la mission**.
- **Stockage local** sur le téléphone : chaque note est enregistrée immédiatement, avec l'heure et la position GPS. Rien n'est perdu si l'application se ferme.
- **Photos** :
  - prises **dans l'application uniquement** (pas d'import depuis la galerie) ;
  - compressées à environ 300–500 Ko ;
  - marquées avec la date, l'heure, la position GPS et une empreinte numérique qui prouve qu'elles n'ont pas été modifiées.
- **Envoi des données en file d'attente** :
  - les notes et commentaires partent dès qu'il y a du réseau ;
  - les photos suivent ensuite, avec une option « photos en Wi-Fi uniquement » ;
  - renvoi automatique en cas d'échec ;
  - indicateur du type « 3 photos en attente ».
- **Soumission possible hors connexion** : le rapport signé est verrouillé sur le téléphone, puis envoyé dès que le réseau revient. Le statut côté serveur est « soumis — en attente des photos » tant que tout n'est pas arrivé.
- **Pas de conflit de données** : un seul agent travaille sur un audit donné, donc deux personnes ne peuvent pas modifier les mêmes données en même temps.

## 7. Rapport d'audit généré

Le rapport est généré automatiquement après la validation du comité qualité. Il est disponible **dans l'espace pro** (`/pro/audits/[id]`) et **en PDF**.

1. **En-tête**
   - N° de rapport, QR code d'authenticité
   - Établissement, secteur, adresse
   - Type d'audit
   - Date, heures d'arrivée et de départ
   - Code de l'agent
   - Version de la grille utilisée
2. **Résultat**
   - Score global (jauge) et statut **ADMIS / NON ADMIS**
   - Les 4 critères en barres
   - Évolution par rapport à l'audit précédent
3. **Points critiques** : liste, avec le motif s'il y a un échec.
4. **Détail par critère** : tableau des sous-critères (note sur 5, commentaire, miniatures des photos).
5. **Points forts** : les 3 meilleurs sous-critères.
6. **Axes d'amélioration prioritaires**
   - Classés par **gain potentiel**.
   - Exemple : « Passer A4 de 2 à 4 = +1,3 point sur votre score global ».
   - Le calcul se fait automatiquement à partir des poids.
7. **Plan d'actions recommandé** : pour chaque action, la priorité, le délai conseillé et le sous-critère visé.
8. **Validation** : signature de l'agent, date de validation par le comité, mention « Le paiement n'a aucune influence sur ce résultat ».
9. **Option IA** : Claude peut rédiger la synthèse à partir des commentaires de l'agent. **L'IA ne modifie jamais une note**, et le texte est relu par l'agent ou le comité.

**Ce que voit le public sur la fiche** : le score global, les 4 critères en %, la date de l'audit et la date du prochain contrôle. Le détail des sous-critères n'est jamais affiché publiquement.

## 8. Règle de réaudit

| Situation | Règle proposée |
|---|---|
| **Audit initial < 80 %**, score entre 70 et 79,9 % | Réaudit possible au plus tôt **30 jours** après, sur demande, avec un plan d'actions déposé |
| **Audit initial < 70 %**, ou un point critique en échec | Parcours B recommandé, réaudit au plus tôt **90 jours** après |
| **Limite** | Au maximum **2 réaudits sans accompagnement par période de 12 mois**. Au-delà, le parcours B est obligatoire. |
| **Contrôle périodique** | **1 audit complet par an** (annoncé, avec une fenêtre de ± 15 jours) **+ 1 contrôle inopiné par an** |
| **Contrôle déclenché** | Signalement grave, incident sanitaire, changement de propriétaire ou de gérant, ou chute des avis (moyenne inférieure à 3/5 sur 30 jours avec au moins 10 avis) |
| **Contrôle < 80 %** | **Retrait immédiat du badge.** Réaudit au plus tôt 30 jours après, ou passage au parcours B. |
| **Contestation (contre-audit)** | Demande dans les **15 jours** suivant le rapport. Réalisé **par un autre agent** dans les 30 jours. **Le résultat du contre-audit est définitif.** |
| **Rotation des agents** | Un agent ne peut pas auditer **deux fois de suite** le même établissement. Un accompagnateur ne peut jamais auditer un établissement qu'il a accompagné (blocage automatique). |
| **Version de la grille** | Un audit utilise la version de la grille en vigueur à la date où il a été planifié |
| **Validité du badge** | 12 mois, renouvelés par l'audit annuel |

## Points à valider
1. **Pondérations** 30 / 25 / 20 / 25 : on les garde ?
2. **Points critiques éliminatoires** (une note de 1 ou moins bloque l'admission) : on les garde ?
3. **Poids doublé** pour les points critiques : d'accord ?
4. **Score masqué à l'agent** pendant la saisie : d'accord ?
5. **Contrôles** : 1 audit annuel + 1 contrôle inopiné par an. Est-ce supportable pour ton modèle économique ?
6. **Délais de réaudit** (30 / 90 jours, 2 tentatives par an) et **contre-audit** : gratuit ou payant ?
7. **Sous-critères** : il faut une relecture par des professionnels de chaque secteur, surtout pour la santé (vérifier les références réglementaires ivoiriennes exactes).
